# Networking

Стек: Netcode for GameObjects 2.x + Unity Multiplayer Services SDK (Sessions / Lobby / Relay). Див. [ADR-001](../Architecture/ADR-001-engine.md).

## Модель авторитету (GDD §13.4)

- **MVP: host-authoritative.** Хост — авторитетний сервер; приватні сесії за кодом/запрошенням.
- Клієнт надсилає **намір** (`RequestGrabHandle(handleId)`), хост перевіряє і змінює стан.
- Фізика (ноші, пацієнт-NPC, двері, швидка) симулюється **тільки на хості**: `NetworkRigidbody` + `NetworkTransform`; у клієнтів rigidbody kinematic.
- Ragdoll не реплікується щокадрово: анімаційний режим + короткий ragdoll-стан з кількома синхронізованими параметрами.
- Від'єднання хоста в MVP = завершення матчу з повідомленням (host migration — пізніше).
- Публічний рейтинговий режим (не MVP) потребуватиме dedicated server.

## Чекліст валідації RPC

Кожен `[Rpc(SendTo.Server)]` перевіряє:

1. **Хто** викликає (`RpcParams.Receive.SenderClientId`) і чи це відомий гравець.
2. **Право** — роль/володіння об'єктом/дистанція до об'єкта.
3. **Стан** — фаза місії та стан об'єкта дозволяють дію.
4. **Повтор** — не дубль і не спам (cooldown / sequence id).

## Відкриті питання (spike LC-001 / LC-009)

- Перенесення нош двома клієнтами: owner = host, клієнти лише надсилають target-позиції ручок? Чи joint-based на хості?
- Водіння швидкої клієнтом-водієм: затримка керування при host-авторитеті; чи потрібна client-anticipation.
- Бюджет трафіку для 4 медиків + NPC + ноші + авто.
